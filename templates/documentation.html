🔌 Apa itu MCP?

MCP (Model Context Protocol) adalah protokol yang menghubungkan asisten suara XiaoZhi dengan knowledge base Xiaozhi Indonesia. Dengan MCP, XiaoZhi bisa membaca materi, mengontrol smarthome, memutar lagu, dan lainnya.

📋 Langkah-Langkah Setup MCP
1
Buka Website XiaoZhi
Kunjungi https://xiaozhi.me dan login ke akun XiaoZhi kamu.
2
Ambil Token MCP
Di halaman XiaoZhi, cari menu "MCP Endpoint" atau "Koneksi MCP".
Salin URL yang dimulai dengan wss://
Contoh: wss://api.xiaozhi.me/mcp/?token=eyJhbGciOiJFUzI1Ni...
💡 Tips: Pastikan menyalin URL LENGKAP, bukan hanya token-nya saja!
3
Tempel di Dashboard Xiaozhi Indonesia
Kembali ke halaman Dashboard Xiaozhi Indonesia.
Cari bagian "Koneksi XiaoZhi" di sidebar kanan.
Tempel URL MCP yang sudah disalin, lalu klik "Simpan".
4
Tunggu Koneksi
Setelah menyimpan, sistem akan mencoba menghubungkan ke XiaoZhi.
Tunggu beberapa detik hingga status berubah menjadi "Terhubung".
5
Verifikasi di XiaoZhi
Kembali ke https://xiaozhi.me.
Cek apakah status MCP sudah "Online" atau "Terhubung".
Jika sudah, XiaoZhi sudah bisa membaca data dari Xiaozhi Indonesia!
⚠️ Troubleshooting MCP
Jika koneksi gagal:
  • Pastikan URL dimulai dengan wss://
  • Pastikan menyalin URL LENGKAP (bukan hanya token)
  • Coba hapus dan simpan ulang token
  • Periksa koneksi internet
🎵 Apa itu YouTube Music?

Fitur YouTube Music memungkinkan XiaoZhi mencari dan memutar lagu dari YouTube langsung ke speaker ESP32 kamu. Audio di-transcode ke format Opus Mono 24kHz secara real-time di server, lalu di-stream ke ESP32 melalui HTTP streaming atau WebSocket.

💡 Highlight:
  • Cukup bilang "Putar lagu [judul]" ke XiaoZhi
  • Format audio: Ogg/Opus (hemat bandwidth, cocok untuk ESP32)
  • Bitrate adaptif: 6k – 32k (default 11k, sangat ringan untuk IoT)
  • Mendukung 3 metode streaming: HTTP, WebSocket frame, dan WebSocket channel

⚙️ Alur Kerja Detail (Step-by-Step)
1
User Minta Lagu via Suara
Kamu bilang ke XiaoZhi: "Putar lagu Bohemian Rhapsody"
XiaoZhi (di xiaozhi.me) mengirim request ke server Xiaozhi Indonesia melalui koneksi MCP.
2
Server Menjalankan Tool play_youtube_song
Server menerima request MCP dan otomatis memanggil tool play_youtube_song(query).
Tool ini menggunakan yt-dlp untuk mencari lagu di YouTube (hingga 5 hasil).
# Dipanggil otomatis oleh MCP:
play_youtube_song(query="Bohemian Rhapsody")

# yt-dlp akan mencari "ytsearch5:Bohemian Rhapsody" di YouTube
# dan mengembalikan video_id, title, duration, stream_url
3
Server Menyimpan Perintah ke Audio Queue
Lagu yang ditemukan otomatis disimpan ke tabel audio_queue di database:
• title: Judul lagu (mis. "Bohemian Rhapsody - Queen")
• stream_url: URL streaming Ogg/Opus (mis. /api/audio/stream/dQw4w9WgXcQ)
• video_id: ID video YouTube
• status: pending (menunggu diambil ESP32)
• owner_id: ID pemilik yang meminta lagu
4
ESP32 Polling & Auto-Binding MAC Address
ESP32 melakukan polling ke server setiap 2-3 detik untuk mengecek perintah audio baru.
PENTING (Mengatasi Status "Menunggu Board"):
ESP32 WAJIB menyertakan MAC Address (?mac={MAC} dan header Device-Id: {MAC}).
Saat server menerima request dengan MAC Address, server otomatis mengikat ESP32 tersebut ke akun user di tabel registered_devices.
Status di Admin & Profil akan langsung berubah dari ⏳ Menunggu Board menjadi kode MAC board berwarna hijau!
GET /api/device/audio/commands?mac={MAC_ADDRESS}&token={MCP_TOKEN}
Header: Device-Id: {MAC_ADDRESS}
💡 Tips Menghubungkan Board:
• Gunakan WiFi.macAddress() di ESP32.
• Jika parameter token juga disertakan, pairing ke akun pemilik terjadi secara instan tanpa perlu setting manual di profil.
5
ESP32 Download & Putar Audio Transcoded (Ogg/Opus Mono 24kHz)
ESP32 menerima stream_url dari server, lalu:
• Membuka koneksi HTTP GET ke stream_url dengan header Device-Id: {MAC}.
• Server melakukan transcoding real-time: YouTube Audio Stream → FFmpeg → Ogg/Opus Mono 24kHz.
• Di dashboard admin, status pengguna yang sedang memutar musik otomatis menampilkan badge hijau 🔊 Sedang Memutar beserta judul lagu yang aktif!
• ESP32 membaca stream audio dan mengirimnya ke DAC I2S (MAX98357A / PCM5102) untuk diputar di speaker.
• Bitrate default: 11kbps (sangat ringan dan stabil untuk ESP32 dengan RAM standar).
6
ESP32 Kirim Konfirmasi Selesai (ACK)
Setelah lagu selesai diputar (atau dihentikan), ESP32 mengirim konfirmasi (ACK) ke server agar antrean ditandai played dan tidak diputar ulang pada polling berikutnya.
POST /api/device/audio/ack
Content-Type: application/x-www-form-urlencoded
Body: command_id={ID}&mac={MAC_ADDRESS}&token={MCP_TOKEN}
📡 Referensi API Lengkap untuk Firmware ESP32

Berikut semua endpoint yang tersedia. Pilih metode yang sesuai dengan kebutuhan firmware kamu.

⚠️ Base URL: Ganti {BASE_URL} dengan domain server Xiaozhi Indonesia kamu.
Contoh: https://xiaozhiscig.biz.id atau URL HuggingFace Space kamu.
1. 📥 Polling Perintah Audio (RECOMMENDED)
ESP32 melakukan polling endpoint ini setiap 2-5 detik. Mendukung autentikasi via token (MCP token), mac (MAC address), atau header Device-Id.
GET {BASE_URL}/api/device/audio/commands?token={MCP_TOKEN}&mac={MAC_ADDRESS}
Parameter Query:
• token (opsional) – MCP token untuk identifikasi user
• mac (opsional) – MAC address ESP32 (format: AA:BB:CC:DD:EE:FF atau esp32-AABBCCDDEEFF)

Header (alternatif):
• Device-Id: MAC address atau ID perangkat

Response (200 OK):
{
  "success": true,
  "commands": [
    {
      "id": "abc123",
      "title": "Bohemian Rhapsody - Queen",
      "stream_url": "{BASE_URL}/api/audio/stream/dQw4w9WgXcQ",
      "video_id": "dQw4w9WgXcQ"
    }
  ]
}
💡 Jika commands kosong ([]), tidak ada perintah baru. Lanjutkan polling.
Server otomatis hanya mengembalikan perintah terbaru dan auto-ack yang lama.
1b. 📥 Polling Legacy (Alternatif)
Endpoint polling lama menggunakan device_id di URL path. Masih didukung tapi disarankan migrasi ke endpoint baru.
GET {BASE_URL}/api/audio/commands/{device_id}
2. ✅ Konfirmasi Audio Diputar (ACK)
Setelah audio selesai diputar, kirim ACK agar perintah tidak diulang di polling berikutnya.
POST {BASE_URL}/api/device/audio/ack
Request Body (JSON):
{
  "token": "{MCP_TOKEN}",
  "command_id": "abc123",
  "mac": "{MAC_ADDRESS}"
}

Response (200 OK):
{ "success": true }
💡 Endpoint ini juga mendukung header Device-Id sebagai alternatif parameter mac.
3. 🔊 HTTP Audio Stream (Ogg/Opus)
Endpoint utama untuk streaming audio. Server melakukan transcoding real-time dari YouTube ke Ogg/Opus Mono 24kHz via FFmpeg.
GET {BASE_URL}/api/audio/stream/{video_id}?br=11k&start=0
Parameter Query:
• br (opsional) – Bitrate audio: 6k, 8k, 9k, 10k, 11k (default), 12k, 16k, 20k, 24k, 32k
• start (opsional) – Posisi mulai dalam detik (default: 0)

Response:
• Content-Type: audio/ogg
• Body: Streaming binary Ogg/Opus
• Cache-Control: no-cache, no-store
💡 Pilih bitrate sesuai kemampuan ESP32:
• 6k-9k: Hemat RAM & bandwidth, kualitas cukup untuk speech/musik sederhana
• 10k-12k: Balance optimal (RECOMMENDED untuk ESP32)
• 16k-32k: Kualitas lebih baik, butuh bandwidth & buffer lebih besar
4. ⚡ Direct Play (Cari & Putar Langsung)
Shortcut: cari lagu dan langsung dapat video_id untuk di-stream. Cocok untuk ESP32 yang ingin langsung putar tanpa melalui queue.
GET {BASE_URL}/api/audio/play_direct?q={search_query}
Response (200 OK):
{
  "success": true,
  "video_id": "dQw4w9WgXcQ",
  "title": "Bohemian Rhapsody - Queen"
}

Lalu stream audio:
GET {BASE_URL}/api/audio/stream/dQw4w9WgXcQ?br=11k
5. 🌐 WebSocket Audio Stream (Advanced)
Streaming via WebSocket dengan raw Opus frames (tanpa Ogg container). Format kompatibel dengan XiaoZhi BinaryProtocol3.
Cocok untuk firmware yang sudah terintegrasi protokol XiaoZhi.
Opsi A – Stream per video:
WS {BASE_URL}/ws/audio/stream/{video_id}?sample_rate=24000&title=Judul%20Lagu

Opsi B – Persistent channel (auto-poll):
WS {BASE_URL}/ws/device/audio/{device_id}
Format binary frame yang diterima:
• Byte 0: type = 0x00 (audio)
• Byte 1: reserved = 0x00
• Byte 2-3: payload_size (uint16 big-endian)
• Byte 4+: raw Opus packet data

Kontrol dari client:
• Kirim text "abort" atau "stop" → hentikan playback
• Kirim text "ping" → server reply "pong"

State messages dari server (JSON):
• {"type": "tts", "state": "start"} → mulai streaming
• {"type": "tts", "state": "sentence_start", "text": "🎵 Judul"} → info lagu
• {"type": "tts", "state": "stop"} → selesai
💡 Persistent Channel (/ws/device/audio/{device_id}): ESP32 cukup buka 1 koneksi WebSocket. Server otomatis polling audio_queue dan langsung stream lagu baru saat ada perintah masuk. Tidak perlu HTTP polling terpisah!
6. 📋 Registrasi Perangkat
Daftarkan ESP32 ke akun user agar server bisa mengenali perangkat saat polling. Auto-registrasi juga terjadi saat polling /api/device/audio/commands dengan parameter mac.
POST {BASE_URL}/api/devices/register
Request Body (JSON):
{
  "device_id": "48:27:E2:81:4A:BC",
  "name": "Speaker Ruang Tamu",
  "type": "esp32"
}

⚠️ Endpoint ini memerlukan login (session cookie).
Untuk registrasi otomatis tanpa login, cukup gunakan parameter mac saat polling.
💡 Format MAC yang diterima:
• 48:27:E2:81:4A:BC (standard)
• 48-27-E2-81-4A-BC (dash-separated)
• 4827E2814ABC (raw hex tanpa separator)
• esp32-4827E2814ABC (dengan prefix esp32)
Semua format dinormalisasi otomatis ke 48:27:E2:81:4A:BC.

1. 📦 Struktur Modul YouTube Audio Poller (C++)
Pada firmware resmi XiaoZhi, pemutar musik YouTube dijalankan melalui komponen background task YouTubeAudioPoller yang terintegrasi langsung dengan AudioService dan Application event loop. Pastikan file main/youtube_audio_poller.h dan main/youtube_audio_poller.cc terdaftar pada main/CMakeLists.txt:
# main/CMakeLists.txt set(SOURCES ... "youtube_audio_poller.cc" "application.cc" "mcp_server.cc" ... )
2. 🏷️ Identifikasi Chip & MAC Address di HTTP Request
Server Xiaozhi Indonesia secara otomatis mendeteksi arsitektur board melalui header X-Device-Chip atau query parameter chip=. Ini memastikan server mengirimkan stream Opus 16kHz untuk ESP32-C3 (agar tidak kehabisan RAM) dan 24kHz untuk ESP32-S3 (agar suara maksimal).

Di dalam main/youtube_audio_poller.cc fungsi StreamAudio():
// Mengambil MAC address dan nama arsitektur chip saat kompilasi std::string mac = SystemInfo::GetMacAddress(); std::string chip = CONFIG_IDF_TARGET; // "esp32c3" atau "esp32s3" char url_buf[256]; snprintf(url_buf, sizeof(url_buf), "%s/api/audio/stream/%s?br=%s&mac=%s&chip=%s", GetStreamUrl().c_str(), video_id.c_str(), current_bitrate.c_str(), mac.c_str(), chip.c_str()); // Header Wajib Identitas Perangkat http->SetTimeout(15000); http->SetHeader("User-Agent", "ESP32-XiaoZhi"); http->SetHeader("Device-Id", mac.c_str()); // Mengikat board ke akun user http->SetHeader("X-Device-Mac", mac.c_str()); http->SetHeader("X-Device-Chip", chip.c_str()); // Identifikasi esp32c3 vs esp32s3 http->SetHeader("Device-Chip", chip.c_str());
💡 Keuntungan Auto-Binding:
Dengan mengirimkan Device-Id: {MAC} dan X-Device-Chip: {CHIP}, server langsung mengenali pemilik board dan menampilkan status streaming aktif di dashboard admin secara instan!
3. 🔊 Sinkronisasi Volume Suara & Dynamic Sample Rate
Agar lagu YouTube diputar dengan volume yang disetel oleh pengguna (bukan volume default 100% atau bisu), dan agar sample rate beradaptasi otomatis antara C3 dan S3:
// 1. Menjaga volume audio speaker tetap sesuai pengaturan pengguna auto codec = Board::GetInstance().GetAudioCodec(); if (codec != nullptr) { if (!codec->output_enabled()) { codec->EnableOutput(true); } ESP_LOGI(TAG, "Playback menggunakan volume aktif: %d%%", codec->output_volume()); } // 2. Membaca header OpusHead dari container OGG if (!seen_head) { if (pkt_len >= 19 && memcmp(pkt_ptr, "OpusHead", 8) == 0) { seen_head = true; sample_rate = pkt_ptr[12] | (pkt_ptr[13] << 8) | (pkt_ptr[14] << 16) | (pkt_ptr[15] << 24); ESP_LOGI(TAG, "OpusHead dideteksi: sample_rate=%d Hz", sample_rate); } continue; } // 3. Mengirim frame Opus ke audio decode queue auto packet = std::make_unique<AudioStreamPacket>(); packet->sample_rate = (sample_rate > 0) ? sample_rate : 16000; // 16k untuk C3, 24k untuk S3 packet->frame_duration = 60; // 60ms Opus frame duration packet->payload.assign(pkt_ptr, pkt_ptr + pkt_len); app.GetAudioService().PushPacketToDecodeQueue(std::move(packet), true);
4. 🛡️ Pencegahan Watchdog Lockup & Safe GUI Scheduling (Khusus ESP32-C3)
Pada ESP32-C3 yang bertipe single-core, terdapat 2 hal krusial yang harus diperhatikan agar ESP32 tidak "nge-stuck" atau mengalami Task Watchdog Triggered (`task_wdt`):
  • Hindari Dispatch GUI di esp_timer: Callback timer berprioritas tinggi (priority 22). Jangan memanggil DisplayLockGuard langsung di dalam timer callback. Jadwalkan update GUI ke main application thread via Application::GetInstance().Schedule(...).
  • Sanitasi Judul Lagu (ASCII Safe): Jangan sertakan emoji unicode 4-byte seperti 🎵 pada string judul label OLED monokrom. Gunakan teks ASCII bersih seperti [PLAY] untuk menghindari infinite loop pada font fallback traversal LVGL.
  • WiFi Power Save Standby: Gunakan WIFI_PS_MIN_MODEM saat idle agar ESP32 tetap responsif menerima ping & pesan MQTT dari router.
// Contoh Safe GUI Scheduling di main/display/lvgl_display/lvgl_display.cc: esp_timer_create_args_t notification_timer_args = { .callback = [](void *arg) { LvglDisplay *display = static_cast<LvglDisplay*>(arg); // Jadwalkan ke thread aplikasi, jangan jalankan di task esp_timer! Application::GetInstance().Schedule([display]() { DisplayLockGuard lock(display); if (display->notification_label_ != nullptr) { lv_obj_add_flag(display->notification_label_, LV_OBJ_FLAG_HIDDEN); } if (display->status_label_ != nullptr) { lv_obj_remove_flag(display->status_label_, LV_OBJ_FLAG_HIDDEN); } }); }, .arg = this, .dispatch_method = ESP_TIMER_TASK, .name = "notification_timer", .skip_unhandled_events = false, };

🔧 Tanya Jawab & Solusi Kendala (Troubleshooting)
❓ Kenapa ESP32-C3 sempat "nge-stuck" atau watchdog reboot saat lagu dimulai?
Penyebab utamanya adalah: (1) Menjalankan callback GUI berdurasi panjang di dalam esp_timer task (prioritas 22) yang menyebabkan IDLE task kelaparan, dan (2) Mengirimkan emoji 🎵 ke label OLED monokrom yang tidak memiliki glyph sehingga terjadi infinite loop pada traversal fallback font LVGL. Solusinya: gunakan Schedule() untuk update GUI dan hindari karakter emoji 4-byte di judul OLED.
❓ Kenapa suara di ESP32-C3 putus-putus atau pecah?
ESP32-C3 memiliki memori internal yang terbatas (tanpa PSRAM). Pastikan firmware mengirim header X-Device-Chip: esp32c3 agar server mengaktifkan profil 16kHz Mono dengan bitrate adaptif 6k–16k. Profil ini membutuhkan alokasi memori minimal dan bekerja lancar tanpa kehabisan SRAM.
❓ Bagaimana dengan ESP32-S3? Apakah bisa langsung 24kHz?
Ya! ESP32-S3 memiliki dual-core dan PSRAM yang melimpah. Saat mengirimkan X-Device-Chip: esp32s3, server otomatis mentranscode audio ke 24kHz Mono/Stereo pada bitrate 16k–32k untuk kejernihan suara maksimal.
❓ Di panel Admin masih tertulis "Menunggu Board (Belum kirim MAC)"?
Pastikan firmware menyertakan header Device-Id: {MAC} atau parameter ?mac={MAC} saat melakukan polling/streaming. Begitu request masuk, server otomatis mendaftarkan MAC ke database akun Anda dan badge berubah menjadi hijau aktif.

📖 Apa itu Knowledge Base?

Knowledge Base adalah database materi yang bisa dibaca oleh XiaoZhi. Kamu bisa menyimpan materi perkuliahan, tugas, catatan, jadwal, dan data API realtime. Saat kamu bertanya ke XiaoZhi, dia akan mencari jawaban dari knowledge base ini.

Materi Perkuliahan
Materi kuliah, modul, atau bahan belajar. Bisa berupa teks panjang yang dipecah per topik.
Tugas Mahasiswa
Daftar tugas, deadline, dan instruksi pengerjaan.
Catatan Dosen
Catatan penting dari dosen atau pengumuman resmi.
Jadwal Kuliah
Jadwal perkuliahan, ujian, atau kegiatan akademik.
Pengumuman & Info
Pengumuman umum, informasi penting, atau berita kampus.
Data dari API (Realtime)
Data yang diambil dari API eksternal seperti cuaca, suhu, harga, dll. Data ini bersifat realtime dan selalu diperbarui.

⚡ Panduan Operasional ESP32-S3 N16R8 (CAM & Standar Non-CAM)
Firmware ini mendukung chip ESP32-S3 N16R8 (16MB Flash + 8MB Octal PSRAM) baik versi dengan modul kamera (CAM) maupun board standar biasa tanpa modul kamera.
💡 Tips Kompatibilitas Board Biasa (Non-CAM):
Firmware memiliki proteksi fail-safe otomatis. Jika board Anda tidak memiliki modul kamera, driver tidak akan crash atau panic, melainkan otomatis melewati inisialisasi kamera dan berjalan normal 100% untuk suara, YouTube, dan MCP tools.
🌐 Alur Konfigurasi Awal (Web Portal 192.168.4.1)
1
Sambungkan ke Hotspot Wi-Fi Bawaan
Saat menyala pertama kali (LED berkedip hijau), hubungkan HP atau Laptop Anda ke hotspot Wi-Fi bernama XiaoZhi-XXXX atau Xichi-Setup (tanpa kata sandi).
2
Buka Portal Konfigurasi di Browser
Buka browser dan kunjungi alamat http://192.168.4.1 untuk membuka portal konfigurasi perangkat keras dan jaringan.
3
Pilih SSID Wi-Fi & Kata Sandi
Pada tab Jaringan Wi-Fi, pilih nama router Wi-Fi Anda (frekuensi 2.4 GHz) lalu masukkan kata sandi dengan benar.
4
Pengaturan Modul Layar & Rotasi
Pada tab Pengaturan Hardware:
  • Tanpa Layar (Headless Audio Only): Pilih ini jika perangkat Anda hanya modul audio tanpa layar.
  • ST7789 240x280 (8-Pin SPI): Untuk modul layar IPS 1.69" / 1.54" 8-pin.
  • ST7789 240x240 (7-Pin SPI): Untuk modul layar 1.3" 7-pin tanpa CS.
  • OLED SSD1306 / SH1106: Untuk layar OLED kecil I2C.
  • Rotasi Layar: Pilih 0° (Normal) atau 180° (Terbalik) sesuai orientasi perakitan.
5
Profil Audio I2S
Pilih INMP441 Mic + MAX98357A Spk (Simplex I2S). Pinout otomatis dikunci pada jalur aman (Mic: GPIO 1, 2, 42 | Speaker: GPIO 39, 40, 41) tanpa bentrok.
6
Modul Kamera ESP32-S3
• Untuk ESP32-S3 Biasa (Tanpa CAM): Pilih Kamera Nonaktif (Hemat Daya & Bebas Pin).
• Untuk ESP32-S3 CAM: Pilih tipe sensor yang terpasang (misal OV2640 2-Megapixel atau OV5640 5-Megapixel).
7
Simpan & Reboot Otomatis
Klik tombol Simpan Konfigurasi. Sistem akan menyimpan data ke NVS Flash dan me-reboot ESP32. Setelah menyala, ESP32 otomatis tersambung ke router Wi-Fi Anda.
🎮 Panduan Lengkap Fungsi Ke-3 Tombol Fisik
Setiap tombol mendukung gestur Klik 1x, Klik 2x Cepat, dan Tekan Tahan (Long Press).
Tombol & Pin Gestur Fungsi Utama Deskripsi / Keterangan
Tombol 1: BOOT
GPIO 0 		Klik 1x Bicara / Stop / Interupsi • Stop lagu YouTube jika sedang diputar.
• Interupsi suara AI jika sedang bicara.
• Mulai mendengarkan tanpa wake-word jika standby.
Klik 2x Auto Play Test Music Langsung memutar lagu pengujian/remix santai dari YouTube.
Tekan Tahan (>3s) Reset Wi-Fi Portal Membuka kembali hotspot Web Config (192.168.4.1) untuk ganti Wi-Fi.
Tombol 2: VOL UP
GPIO 14 		Klik 1x Volume +10% / Zoom In • Naikkan volume speaker +10%.
• Jika live camera aktif: Zoom In (1x → 2x → 3x).
Klik 2x Rotasi Layar 180° Memutar tampilan layar ST7789 180 derajat seketika tanpa restart.
Tekan Tahan Volume Maksimal (100%) Mengatur volume speaker langsung ke batas tertinggi 100%.
Tombol 3: VOL DOWN
GPIO 46 		Klik 1x Volume -10% / Zoom Out • Turunkan volume speaker -10%.
• Jika live camera aktif: Zoom Out perkecil gambar.
Klik 2x Switch Mode (XiaoZhi ↔ Chronchi) Beralih antara mode Asisten Suara AI dan mode Jam Pintar / BLE Companion.
Tekan Tahan Mute Suara (0%) Membisukan audio seketika (Volume 0%).
📌 Referensi Pinout Hardware ESP32-S3
[ Microphone INMP441 (I2S Input) ] • SCK (Bit Clock) : GPIO 2 • WS (Word Select) : GPIO 1 • SD (Serial Data) : GPIO 42 • L/R & GND : GND • VDD : 3.3V [ Speaker MAX98357A (I2S Output) ] • BCLK (Bit Clock) : GPIO 40 • LRC (Word Select) : GPIO 41 • DIN (Serial Data) : GPIO 39 • GND : GND • VIN : 5V (Disarankan) atau 3.3V [ Layar ST7789 SPI (Opsional) ] • SCL / CLK : GPIO 12 • RES / RST : GPIO 47 • SDA / MOSI : GPIO 11 • CS : GPIO 45 (Khusus 8-Pin) • DC / RS : GPIO 48 • BL / PWM : GPIO 38 [ Tombol Fisik (Active Low - Internal Pull-up) ] • Tombol BOOT / AI Voice : GPIO 0 • Tombol Volume UP : GPIO 14 • Tombol Volume DOWN : GPIO 46

❓ Pertanyaan Umum
Q: XiaoZhi tidak bisa membaca materi saya?
A: Pastikan koneksi MCP sudah Online di Dashboard. Jika belum, ulangi langkah setup MCP.
Q: Lagu YouTube tidak bisa diputar?
A: Periksa:
  • Fitur YouTube harus diaktifkan oleh admin
  • ESP32 terhubung ke WiFi
  • Speaker terhubung ke ESP32
  • MCP dalam status Online
Q: Smart home tidak merespons?
A: Pastikan:
  • MCP dalam status Online
  • Perintah suara sesuai dengan nama ruangan
  • Gunakan perintah yang jelas seperti "Nyalakan" atau "Matikan"
Q: Berapa banyak materi yang bisa disimpan?
A: Tergantung batas yang ditetapkan. Hubungi admin jika butuh kapasitas lebih.
Q: Bagaimana cara mengubah tema?
A: Di sidebar bawah, ada dropdown "Tema". Pilih tema yang diinginkan: Neo Brutalism, Dark, atau Original.
Q: Apakah data saya aman?
A: Ya! Semua data dienkripsi menggunakan Fernet encryption. Token MCP disimpan dalam bentuk terenkripsi di database.
Q: Bagaimana cara menghubungi admin?
A: Hubungi admin melalui kontak yang tersedia di aplikasi atau melalui kontak resmi.
